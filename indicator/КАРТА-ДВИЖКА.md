# Карта движка v5 (из `trener_v8.pine`)

Это **точные правила**, по которым ваш существующий индикатор открывает
сделки. Ничего не додумано — выписано из кода, функция `f_decide`
(строки 250–345) плюс обвязка.

Сверено с `engine_v5.py` повердиктно: 9416 из 9416, сделки 939 из 939.

---

## Из чего движок вообще смотрит

**Очередь из 5 последних меток 2/2.** Всё. Больше ничего.

```
q_lab  — подписи: HH / LH / HL / LL
q_prc  — цена метки
q_side — "high" или "low"
q_conf — бар, на котором метка подтвердилась
```

Очередь длиной ровно 5 — новая метка выталкивает самую старую.
Пивоты 2/2, подтверждение через 2 бара.

**Чего движок НЕ видит:**

* метки 5/5 — рисуются на графике, но в решении не участвуют
* тренд D3 — считается, но используется только в необязательном фильтре
* счёт точек (0)–(5) — его в этом индикаторе просто нет
* запас, уровень, колена, мутность, боковик — ничего этого нет

## Каскад решения

Запускается **только** на подтверждённой триггерной свече
(`shape_ok and barstate.isconfirmed`). Проверки идут строго по порядку,
первый провал = пропуск.

### 0 · Недельный предохранитель (по умолчанию ВКЛ)
```
неделя набрала <= -3.0R  →  «стоп-неделя», входов до понедельника нет
```
Замер: +53.2R → +80.1R, худшая неделя −9R → −3R.
Выключение возвращает эталонные 939 сделок.

### 1 · Есть метки
```
очередь пуста  →  «нет меток»
```

### 2 · Направление — по ПОСЛЕДНЕЙ метке очереди
```
HL или LL  →  LONG
LH или HH  →  SHORT
```
Это **возврат к среднему**: движок покупает от нижней метки и продаёт
от верхней. Никакого «по тренду» здесь нет.

### 3 · Заморозка
```
последняя метка LL или HH  И  лаг <= 1 бар  →  ПРОПУСК
```
Лаг — сколько баров прошло с подтверждения метки. То есть свежий
экстремум-разворот не торгуется, ждём хотя бы 2 бара.
Самая частая причина после «нет RR» — **25.0%** всех триггеров.

### 4 · Размер свечи
```
(high - low) / close * 100  >  0.317%  →  ПРОПУСК «бол.свеча»
```
0.317% — это P80 по всей истории золота 1H. Есть режим «авто»
(перцентиль по растущему окну), по умолчанию фикс.
**15.5%** триггеров.

### 5 · Против тренда — голосование в очереди
```
up = сколько HH и HL среди 5 меток
dn = сколько LH и LL среди 5 меток

had_slom = есть ли в очереди переход HH→LL или LL→HL

если нет слома и SHORT и up >= (3 когда последняя HH, иначе 4)  →  ПРОПУСК
если нет слома и LONG  и dn >= 4                                →  ПРОПУСК
```
Асимметрия «3 против 4» — не опечатка, так в коде. Шорт от HH при
трёх бычьих метках уже запрещён, а лонг требует четырёх медвежьих.
**10.3%** триггеров.

### 6 · Свежий слом
```
предпоследняя→последняя = HH→LL  или  LL→HL  →  ПРОПУСК «слом»
```
Ждём подтверждения. **5.4%** триггеров.

### 7 · Стоп
```
LONG :  sl = low  * (1 - 0.001)
SHORT:  sl = high * (1 + 0.001)
```
За экстремум **триггерной свечи**, буфер 0.1%.
Проверка, что стоп по нужную сторону от входа, иначе «стоп?».

Вход — по `close` триггерной свечи.

### 8 · Магнит (цель)
```
risk = |вход - стоп|

кандидаты = метки очереди со стороны "high" (для лонга) / "low" (для шорта),
            которые выше входа (лонг) / ниже входа (шорт)

сортируем по близости к входу
первая, у которой |цена - вход| / risk >= 3.0  →  это TP

нет такой  →  ПРОПУСК «нет RR»
```
Самая частая причина отказа — **30.5%** триггеров.
Цель ищется только среди тех же 5 меток очереди.

### 9 · Запрет хвоста
```
последние 5 меток заканчиваются на:
    LL>HH        →  запрет
    HH>LH        →  запрет
    LL>LH>HL     →  запрет
    HH>LL>LL     →  запрет
```
**3.3%** триггеров. В коде помечено как «крупнее: v2-глаз входит!» —
то есть это ситуации, где глаз хочет войти, а движок запрещает.

### 10 · ВХОД
Всё прошло — открывается позиция.
**10.0%** триггеров.

## Необязательный фильтр (по умолчанию ВЫКЛ)

```
ВХОД + LONG + тренд D3 = БОКОВИК  →  ПРОПУСК
```
Лонги в боковике на золоте: −33R за 9 лет (шорты при этом +15R).
С фильтром +53.2R → +86.2R, walk-forward +26R вне выборки.
Оговорка в коде: не бесплатен, минусовым был в 6 годах из 8.

## Ведение позиции

* до **5** позиций одновременно
* закрытие только по SL или TP, ничего не двигается
* SL и TP в одном баре — считается **SL** (консервативно)
* R = RR при TP, −1.0 при SL
* медиана жизни сделки **4 бара**, 80% закрываются за 17 баров

## Тренд D3 — что это и зачем считается

Отдельный от каскада блок. Тренд по **медленным 5/5** меткам:

* рождается на паре `HH+HL` (восх) или `LH+LL` (нисх)
* уровень — последний HL (восх) или LH (нисх), обновляется новыми метками
* умирает, когда **тело** свечи закрылось за уровнем; буфера нет намеренно
* контр-метки тренд не убивают

Медиана тренда 26 баров против 6 у 2/2 (замер на 9 годах золота).

Это прямой предок нынешнего движка 5/5 в `gde_my_v5/v6`, но без
`fibDepth`, без рывка, без провизорного уровня и без счёта точек.
